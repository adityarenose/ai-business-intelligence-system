# AI-Powered Business Intelligence & Decision Support System

## Project Overview

This project is an end-to-end business intelligence dashboard for sales performance, customer analytics, churn prediction, and grounded natural-language business questions. Flask serves the dashboard and REST API. Pandas and NumPy provide the default analytics layer over generated CSV files, while MySQL scripts and Power BI documentation support a database-backed reporting workflow.

## Business Problem

Businesses often have sales and customer records but lack a single view of revenue, customer value, regional performance, and retention risk. This system turns those records into executive KPIs, trend analysis, transparent customer segments, churn predictions, and data-backed recommendations.

## Key Features

- Executive KPIs: revenue, orders, customers, average order value, and churn rate.
- Monthly revenue, category, product, city, customer spending, and segment analysis.
- Churn prediction with validated customer input and low/medium/high risk levels.
- Grounded assistant questions for supported business analytics.
- Responsive HTML, CSS, and JavaScript dashboard served by Flask.
- MySQL schema, reporting queries, and Power BI data-model guidance.
- Automated tests for the API, ML pipeline, assistant safeguards, and SQL validation.

## Data Provenance

The project uses reproducible synthetic e-commerce data. It is generated by `src/data_generator.py` with a fixed default seed and does not represent real customers, transactions, or company performance. The smaller `data/sample/` CSV files are suitable for inspection and are committed. The larger `data/raw/` CSV files are generated locally and excluded from Git by `.gitignore`.

## System Architecture

```text
CSV data or MySQL tables
          |
          v
Pandas analytics and feature engineering
          |
          +--> Flask REST API --> browser dashboard
          |
          +--> scikit-learn churn model
          |
          +--> approved assistant analytics --> grounded answer
          |
          +--> MySQL / Power BI reporting workflow
```

The default API path reads `data/raw/*.csv`. MySQL access is centralized in `src/database.py` and is available for imports and read-only SQL utilities when configured. Database credentials are never accepted from the frontend.

## Database Structure

`database/schema.sql` defines four InnoDB tables:

- `customers`: customer demographics, tenure, spend, support calls, purchase frequency, and recorded churn target.
- `products`: product names, categories, and prices.
- `orders`: customer orders, dates, totals, and payment methods.
- `order_items`: product lines, quantities, prices, and line totals.

Foreign keys connect customers to orders and orders/products to order items. `database/queries.sql` contains read-only reporting examples. `database/seed.sql` is a Windows `LOAD DATA INFILE` example with a machine-specific path; update its paths or use a server-approved import directory before running it on another machine.

## Machine Learning Component

`src/ml_model.py` builds customer-level features, compares balanced logistic regression and random forest pipelines, evaluates precision, recall, F1, accuracy, ROC-AUC, and a confusion matrix, then selects the better validation F1 model. The trained pipeline is saved locally as `models/churn_model.pkl` with metadata in `models/churn_model.metadata.json`; both are ignored because they are reproducible generated artifacts.

## GenAI and AI Assistant Component

`src/ai_assistant.py` maps a supported question to an allow-listed analytics function before returning verified records, insights, and recommendations. It never executes model-generated code. With `LLM_PROVIDER=none` (the default), responses are deterministic. An optional OpenAI-compatible endpoint can rephrase verified results using `LLM_PROVIDER=compatible`, `LLM_API_KEY`, `LLM_MODEL`, and `LLM_BASE_URL`; malformed or unavailable provider responses fall back to the deterministic answer.

## API Endpoints

Run the backend from the repository root with `python -m api.app`. It listens on `http://127.0.0.1:5000`.

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Health check |
| GET | `/api/summary` | Combined dashboard KPIs and datasets |
| GET | `/api/sales/trend` | Monthly revenue |
| GET | `/api/sales/categories` | Category revenue and units |
| GET | `/api/sales/products` | Product revenue and units |
| GET | `/api/sales/cities` | City revenue, orders, and customers |
| GET | `/api/customers/segments` | Customer counts by segment |
| GET | `/api/customers/churn` | Churn KPIs and city breakdown |
| POST | `/api/predict-churn` | Predict one customer's churn risk |
| POST | `/api/ask` | Ask a supported grounded question |

The prediction request must be JSON with `age`, `gender`, `city`, `tenure_months`, `monthly_spend`, `support_calls`, `purchase_frequency`, `total_orders`, `total_spent`, `avg_order_value`, `segment`, and `payment_method`. The assistant request is `{"question": "Which category generated the most revenue?"}`.

## Power BI Component

The optional Power BI workflow imports `customers`, `products`, `orders`, and `order_items` from MySQL, models their relationships, and defines DAX measures for revenue, orders, customers, average order value, and churn. Follow [powerbi/README.md](powerbi/README.md). Use a dedicated read-only reporting account and keep its password outside the repository. No `.pbix` file is included in the current project.

## Installation

From the repository root in PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks activation, run `Set-ExecutionPolicy -Scope Process Bypass` for the current terminal or invoke `.venv\Scripts\python.exe` directly.

## Generate the Local Dataset

The API expects the larger generated files in `data/raw/`. Generate both raw and sample datasets with:

```powershell
python -m src.data_generator
```

To generate a smaller local raw dataset, use for example:

```powershell
python -m src.data_generator --customers 500 --products 20
```

The command overwrites generated CSVs in `data/raw/` and `data/sample/` by default.

## Environment Variables

Copy `.env.example` to `.env` and replace placeholders only when using MySQL or an external LLM:

```powershell
Copy-Item .env.example .env
```

Set `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, and optionally `DATABASE_URL` for MySQL. Leave `LLM_PROVIDER=none` for the local deterministic assistant. For a compatible provider, set `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL`, and `LLM_BASE_URL`. Never commit `.env`, keys, passwords, or provider credentials.

## MySQL Setup

1. Start MySQL and create the database by executing `database/schema.sql` in MySQL Workbench or another MySQL client.
2. Generate the raw CSVs with `python -m src.data_generator`.
3. For a local Windows import, update the four paths in `database/seed.sql` to the clone's absolute paths, confirm MySQL `secure_file_priv` permits them, and execute the script. Alternatively, place the CSVs in the server-approved import directory and adjust the script there.
4. Set the database variables in `.env` and use a least-privilege account. The Flask dashboard still defaults to CSV analytics; MySQL is the optional database/reporting path in the current implementation.

## Run the Backend and Frontend

After generating data and training the model, start the backend:

```powershell
python -m api.app
```

Open `http://127.0.0.1:5000/` in a browser. There is no separate frontend build or frontend server: Flask serves `frontend/index.html`, `frontend/app.js`, and `frontend/styles.css`.

## Train and Use the ML Model

Train the model after generating `data/raw/`:

```powershell
python -m src.ml_model
```

This creates the ignored model files required by `POST /api/predict-churn` and the high-risk assistant question. Start the API afterward and use the dashboard form or the endpoint with the required JSON fields described above.

## Example AI Assistant Questions

The current allow-list supports questions such as:

- Which city has the highest sales?
- What are our top 10 products?
- How many customers have churned?
- What percentage of customers have churned?

## Project Limitations

- Data is synthetic and cannot establish real business performance.
- The default application reads CSV files into memory; the MySQL path is not the default API data source.
- The assistant supports a fixed set of question patterns rather than unrestricted natural-language analytics.
- External LLM usage is optional and requires a compatible provider and secret outside source control.
- The saved model is a baseline decision-support model, not a production risk or credit decision system.
- Power BI requires local MySQL, connector, credentials, and report configuration; no PBIX file is included.
- Authentication, authorization, rate limiting, and production deployment configuration are not implemented.
